## 三、近期完成（2026-09-15）

### AI 小助手：补齐查询范围 + 按权限点过滤工具

原本有**两个**问题，都不是小毛病：

1. **提示词在教模型撒谎** —— 系统提示词写着能查「线索、客户、商机、**报价单、合同、产品、回款、发票**」，
   但后四个域**根本没有工具**。模型被这么告知后会去调不存在的 `search_quotations`，
   然后要么编数字、要么回「查不到」。
2. **工具完全没有权限过滤** —— `AiToolRegistry.specs()` 把全部工具无条件发给模型，
   `execute()` 也只校验「工具名在册」。于是**任何登录用户**都能让 AI 去查线索/客户/合同，
   只靠行级数据权限兜底。财务账号页面上看不见线索菜单，AI 里却能问——两边不一致。

**做法**：`AiTool` 接口加 `default String permission()`；`AiToolRegistry` 成为唯一的过滤点
（`specs()` 过滤 + `execute()` 再校验一次做纵深防御），权限匹配**复用
`SaTokenConfig` 覆写过的 `SaStrategy.instance.hasElement`**，所以超管 `*:*:*` 与
`crm:lead:*` 部分通配的语义都自动继承，没有第二份实现。

**工具从 9 个扩到 25 个**：新增报价单、产品、产品分类、回款、发票、线索池、客户公海，
以及系统设置的 9 个（人员/部门/角色/字典/单位/公告/编号规则/登录日志/操作日志）。

- ⚠️ **财务工具写在 `crm-module-finance` 模块里**：`crm-module-crm` 看不见 finance（会成环），
  而 finance 依赖 crm。Spring 默认扫描覆盖全部模块，注册表的 `List<AiTool>` 会把三处都收进来。
- ⚠️ **行为收窄**：给现有 9 个工具补权限点后，**财务账号失去了查询线索/客户工具的能力**
  —— 这是有意的，与页面上的菜单权限对齐。
- ⚠️ **两个日志工具 + `search_users` 查的表不在数据权限白名单里**，行级过滤对它们不生效，
  `permission()` 是唯一闸门（这两个权限码种子里只授给超管）。
- 新增 `AiToolRegistryTest`（14 个断言）锁住过滤行为 —— AI 工具链此前**零测试**。
- 顺带修了 `SearchLeadsTool` / `SearchCustomersTool` 里**写错的字典码值说明**
  （来源「4地推 5转介绍 6广告」、行业「6零售 7建筑」与 `sys_dict_data` 不符，模型会照着答错）。

### 顶栏「个人信息」：从占位提示到真能用

顶栏用户下拉里的「个人信息」此前点下去只弹一句「尚无对应接口，暂未实现」。
两侧各缺一块，**任何一块单独补都不成**：

1. **前端缺回显来源** —— `GET /auth/me` 的 `UserInfoRespVO` 里没有
   `phone / email / avatar / nickname`，而 2.8 的 `PUT /auth/profile` 是
   `not_null` 语义（不传 = 不改），回显不到当前值的话，用户只改个姓名就会把
   手机号、邮箱、头像**一起提交成 null**。
2. **前端连函数都没写** —— `api/auth.js` 里没有 `updateProfile`。

**做法**：给 `UserInfoRespVO` 补这 4 个字段（MapStruct 同名自动映射，`AuthConvert` 没动），
而不是另开 `GET /auth/profile` —— 前端 `userStore.userInfo` 本来就存着 `/auth/me` 的结果，
弹窗打开时**零额外请求**。新增 `layout/components/ProfileDialog.vue`（复用
`ConfigFormDialog` + `useFormDialog`，与「修改密码」同款）+ `components/form/AvatarUpload.vue`
（圆形单图，走通用 `/system/file/upload` 且**不传 bizType/bizId** = 临时上传，不写 `sys_attachment`）。

- ⚠️ **只提交与打开弹窗时不同的字段**。这既是 `not_null` 接口该有的用法，也是**防误清**：
  后端若还没重启到最新版本，`/auth/me` 不返回那几项，无脑全量提交就会把用户的手机号清空。
- ⚠️ **手机号正则放行空串**（`^$|^1[3-9]\d{9}$`）：「清空手机号」是合法操作，
  而空串在 `@Pattern` 下**不通过**（只有 `null` 才视为通过）—— 改之前用户一点保存就得到
  「手机号格式不正确」，而他什么都没填错。
- ⚠️ **`avatar` 为空时 `/auth/me` 的 JSON 里根本没有这个 key**（全局 Jackson 的
  `default-property-inclusion: non_null`）。前端按「可缺省」处理：`emptyForm` 里默认空串，
  比对时 `origin[k] ?? ''` 归一化，所以不会被误判成「用户清空了头像」。
- 顺带更正：手机号是**明文存储**的，接口文档 2.8 原写「加密存储」与代码不符，已改。

> **2026-09-15 补记**：前端最终把「个人信息」做成了**整页**（`views/profile/index.vue`，
> 原型下拉里本来就有「个人信息 / 个人资料」两项），弹窗版 `ProfileDialog.vue` 已删除。
> 整页是只读展示，所以后端又补了一个 `UserInfoRespVO.gender`（中文口径，
> `AuthConvert` 里必须 `ignore` 掉再由 `DisplayEnumTranslator.genderToText()` 填，
> 否则 MapStruct 会把 Integer 直接映射成 "1"/"2"）。
> 页面上原来那行「出生日期」已去掉 —— **`sys_user` 表里根本没有这一列**，
> 取 `userInfo.birthDate` 恒为 undefined，界面上永远是「—」。

**已验证**（起第二个实例在 8081 跑上述新代码，脚本走真实 HTTP）：
登录 → `/auth/me` 确实下发 nickname/phone/email → 改手机号后重读是新值（真落库）→
传空串能清空 → 传非法手机号被 400 拦下 → 还原后与初始值完全一致（没留残留）→
请求体里夹带 `username`/`status` 被忽略。

## 六、环境要点

### 怎么跑起来

```bash
# 后端
mvn clean package -DskipTests
java -jar crm-server/target/crm-server.jar

# 前端
cd aurum-crm-ui && npm install && npm run dev
```

### ⚠️ 邮件是新的启动前置

**不配邮件，注册 / 邮箱登录 / 找回密码全都用不了**（返回 `1009`）。
配置在 `crm-server/src/main/resources/application-dev.yml` 的 `spring.mail.*`。

**用之前必须在 163 网页版开启 SMTP 服务**（设置 → POP3/SMTP/IMAP）——
服务没开时，即使授权码完全正确，认证也一律返回 `535 Error: authentication failed`，
**和「授权码填错」是同一个错误码**，极难自查。详见 README「常见问题」。

### 凭证写在配置里（团队约定）

数据库 / Redis / OSS / 邮箱的密码都**直接写在 `application-dev.yml`**。
这是有意的：多人协作时所有人拉下来就能跑，用环境变量的话每人还要各自配一遍。
代价是凭证进版本库，所以**仓库必须保持私有**，对外交付前把这五处换成占位符。
